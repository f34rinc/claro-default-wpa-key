Wi-Fi security briefing · WPA2 default keys

The SSID is
broadcasting the password.

…well, most of it.

On affected Claro gateways the factory Wi-Fi key is carved from the device MAC — and every byte of it is on the air. The SSID hands you 6 of the 8 characters; the BSSID hands you the rest. Usually no handshake, no cracking — just derive it.

The catch — and the fix: this only works while the gateway is still on its factory SSID and password. Change either and there's nothing to derive.

All MACs, SSIDs and keys shown are fabricated examples. Affected: older hardware (~2021 and earlier). For authorised / defensive use only.

01

Where the characters come from

On affected gateways the default key is the device MAC's last four octets, uppercased. And the beacon publishes every one of those octets — three in the SSID, one in the BSSID's OUI.

02

The last byte isn't secret — it's the OUI

You might expect the leading byte to be the one hard part. It usually isn't: on the common single-OUI gateway the Wi-Fi radio and the modem sit on the same vendor OUI, and the radio's BSSID is broadcast in every beacon — so that byte is right there in the air.

BSSID — the Wi-Fi radio

A0:B1:C2:0C:E4:59

In every beacon. Its OUI is A0:B1:C2 — octet 3 is C2.

Device MAC — the key source

A0:B1:C2:3A:9C:2D

Same OUI A0:B1:C2. So octet 3 = C2 — the password's leading byte, already public.

The exception — split-OUI gateways. Some units — systematically, the ARRIS/CommScope models — are really two devices in one shell: the DOCSIS modem and the Wi-Fi router draw MACs from different OUI blocks — e.g. radio C8:52:61 while the modem that keys the password is A8:70:5D. There the BSSID's octet 3 (61) is not the leading byte (5D), so it can't be read off the beacon — that's what the 256-guess fallback is for, and it resolves against a handshake in under a second. This isn't rare, it's under-counted: split can't be told from single by a beacon alone, and split owners tend to rename — so passive scans miss it. Scanning a metro capture directly for the ARRIS OUI turned up three distinct ARRIS gateways, every one renamed.
03

A 2³² key that collapses to one

On paper an 8-hex WPA2 key is 2³² — about 4.3 billion possibilities. Read the SSID and the BSSID and it drops to a single candidate; even the worst case (last byte unreadable) is just 256.

A "strong" WPA2 network reduced to a lookup. No handshake, no GPU — the network is naming its own password to anyone in range.

04

Read it off the air — or crack the fallback

The primary path needs nothing but a scan: take the BSSID's octet 3 and the SSID tail, and you have the key. If the byte genuinely can't be read, a captured handshake + a 256-guess mask closes it out in under a second.

05

Measured, not theorised

Verified against 10 Claro gateways spanning 7 hardware vendors — by deriving the key from live handshakes, and by reading factory labels, ANATEL certification photos, and on-label QR codes. A passive metro survey then found 1,000+ more distinct gateways live on default across 20+ vendor blocks — every one single-OUI (the split-OUI ARRIS class is under-counted by passive scans; see the note above).

It's the model/era, not the vendor. Two vendors appear on both sides — an older model that's affected, a newer one that isn't. So a CLARO_<hex> SSID means worth testing, never guaranteed vulnerable. The SSID format is universal across all 10 devices; the weakness is not.
06

Four mistakes, compounding

Any one is survivable. Stacked together, they turn a "strong" WPA2 network into a lookup.

Deterministic from a low-entropy seed

The key is a pure function of the MAC — an identifier, not random key material.

The seed is broadcast

The SSID publishes the MAC's last 3 octets and the BSSID publishes the OUI — together, all 4 password octets.

A tiny alphabet, no stretching

Uppercase hex only, never hashed or salted. 8 hex = 32 bits at best; after the leaks, as little as zero.

An offline-attackable protocol

WPA2's captured handshake makes even a trivial space testable, undetected — and here you often don't even need it.

It's a whole family. This pattern has hit ISP gateways for years. Whenever a default key is an algorithm over a public identifier, that algorithm eventually gets published and the whole fleet's defaults become recoverable.

07

The fix

If you own the gateway

  • Change the Wi-Fi password to a long, random passphrase. 20+ random characters defeat this outright — the real fix.
  • Change the SSID so it stops echoing the MAC. On its own that only hides the tail, so do both.
  • Treat any device still on its factory CLARO_<hex> name as effectively open — and check whether yours is a pre-2022 model.

If you're the vendor / ISP

  • Provision full-entropy, per-device random keys — stored, never computed from the MAC.
  • Never derive the SSID and the key from the same secret, and never put key bytes in a broadcast field.
  • Force a password change on first setup.
The good news: Claro's 2022+ hardware already ships full-entropy random keys — the fix is proven and shipping. The residual risk is the installed base of older units, and for those the cure is one setting: change the password.
08

Scope — a dated line, not a fleet

Across the devices measured, the switch to random keys tracks the manufacture date — on both coax and fibre, across vendors. The affected window is roughly 2019–2021.
